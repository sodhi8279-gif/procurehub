RGS Infra ProcureHub version 6.5

Developed by SS Sodhi

Procurement for multi-site water supply & sewerage projects: site demands → categorise → RFQ to vendors → comparative → PO → receipt → dispatch → site confirmation.

Updating from an earlier version — your data stays.
  1. Unzip the new version anywhere (for example in Downloads) and double-click RGS-ProcureHub.exe.
  2. From version 5.3 the program does the rest: if an older ProcureHub is still running it closes it, finds the folder that holds your data (for example D:\RGS-ProcureHub\ProcureHub-Data), copies itself there and restarts from there in a new window. If Windows asks for permission, click Yes.
  3. Check the result: the black window and the bottom of the menu in the browser show version 6.5.0, and the black window shows Data folder: …\ProcureHub-Data of your real folder. Browsers that were open reload automatically.
  4. Never delete or replace the ProcureHub-Data folder. It holds everything you entered.
How it works in one line: you run RGS-ProcureHub.exe on one computer (the "server"). Everyone else — HQ staff and all 20 sites — just opens its address in a web browser on any phone, tablet or PC and signs in. Nothing is installed at site.

1. Start it on the HQ computer (5 minutes)

  1. Copy the whole ProcureHub folder to the computer that will be the server, e.g. D:\RGS-ProcureHub. Pick a PC that stays switched on during working hours. Do not run it from inside the zip file.
  2. Double-click RGS-ProcureHub.exe.
    • If Windows shows "Windows protected your PC", click More info → Run anyway (the program is new and not yet signed).
    • ProcureHub sets up Windows Firewall itself the first time it runs from a folder: when Windows asks "Do you want to allow this app to make changes?", click Yes. The black window then shows Windows Firewall: allowed for other computers.
  3. A black window opens showing the addresses, and your browser opens ProcureHub. Keep the black window open — closing it stops ProcureHub for everyone (you can minimise it).
  4. First time only: fill in your company name and create the HQ administrator login.
  5. Go to Settings & users: upload your logo and fill in company details. Then add Projects (with a site photo), Vendors (tick the categories each supplies) and one Site user per project.
New in version 2: picture catalogue of 117 standard water supply & sewerage items so sites pick instead of type; photos on demands, receipts, goods receipts, projects, items and your logo; site stock with daily material-use entries; transfers of surplus material from one site to another; printable challans and requisitions; notifications, search, dark mode, and a phone layout with a bottom menu for sites.

2. Connect all your projects across the country

Inside your office, others can already use the "On the office network" address shown in the black window (e.g. http://192.168.1.20:8080). Sites in other cities need an internet address. Choose one option:

Option A — Cloud server (recommended)

Rent a small cloud server (₹500–1,500/month from any provider, e.g. AWS Lightsail, DigitalOcean, Hostinger VPS, Azure). It is always on, has a fixed address and does not depend on your office PC or power.

Option B — Keep it on the HQ PC

Free. Use Cloudflare Tunnel to give the HQ PC a secure https web address. The HQ PC and internet must stay on whenever sites work.

Option A: cloud server (Linux)

  1. Create an Ubuntu server and note its public IP. Point a sub-domain such as procure.yourcompany.com to that IP in your domain's DNS (an "A record").
  2. Upload procurehub-linux and procurehub.service to /opt/procurehub/ and install it as a service so it starts automatically: 
    sudo mkdir -p /opt/procurehub && sudo mv procurehub-linux /opt/procurehub/
sudo chmod +x /opt/procurehub/procurehub-linux
sudo cp procurehub.service /etc/systemd/system/
sudo systemctl enable --now procurehub
  3. Add free automatic https with Caddy: 
    sudo apt install -y caddy
echo 'procure.yourcompany.com {
  reverse_proxy localhost:8080
}' | sudo tee /etc/caddy/Caddyfile
sudo systemctl restart caddy
  4. Open https://procure.yourcompany.com — set up as in step 1. To move existing data from the HQ PC: on the PC, Settings → Backup → Full backup (.zip); on the server, Settings → Backup → Restore from backup.

Option B: Cloudflare Tunnel on the HQ PC

  1. Create a free account at dash.cloudflare.com and add your company domain (Cloudflare guides you to change the domain's name servers).
  2. In Cloudflare, open Zero Trust → Networks → Tunnels → Create a tunnel, choose Cloudflared, name it "procurehub", and run the Windows install command it shows on the HQ PC (in Command Prompt as Administrator). It installs as a Windows service.
  3. Add a Public hostname: sub-domain procure, your domain, service type HTTP, URL localhost:8080. Save.
  4. Sites now open https://procure.yourcompany.com. No router changes or static IP needed, and the connection is encrypted.
Quick trial without a domain: install cloudflared and run cloudflared tunnel --url http://localhost:8080. It prints a temporary https://….trycloudflare.com address. It changes every time, so use it only for testing.
Do not open port 8080 on your office router directly to the internet without https — passwords would travel unencrypted. Use Option A or B.

Start automatically with Windows (Option B)

Press Win+R, type shell:startup, press Enter, and put a shortcut to RGS-ProcureHub.exe in that folder. In the shortcut's Properties → Target, add --no-browser at the end.

New in 5.2 — GST for each item
  • Item catalogue: each item can have its own GST % and HSN code. New quotations start with that GST.
  • Quotations: every line has its own GST % box. "Apply to all lines" sets one rate for the whole quote. Pasting from Excel accepts two columns (rate and GST %).
  • Comparative and POs: lowest price, landed totals and PO values use each line's GST. One PO can mix 5%, 12%, 18% and 28% items. The PO shows HSN and a GST line for each rate.
  • Correcting an existing PO: open the PO → GST & HSN, change the rates, Save. Optionally the catalogue remembers them.
  • Old quotations and POs keep the GST they had; nothing is recalculated unless you change it.
New in 5.3 — HQ store, documents, vendor categories
  • HQ store (menu): Stock in store shows every item lying at HQ with quantity received, sent to sites, in store, reserved for approved site demands, free, last inward and days in store; tap an item for its full in-and-out register. Record inward against a PO or without a PO (purchased without PO, opening stock, other). Send material to a site sends any free stock to any site on a challan. Inward (GRN) lists every inward with documents and a printable inward note.
  • Direct or via HQ store: on a PO, until anything is received, switch between delivery to the HQ store and direct delivery to sites.
  • Documents: wherever a challan, invoice, quotation or receipt copy is attached, click Browse files (or drag files onto the box) to upload photos (JPG, PNG) or PDF files up to 12 MB each. Documents can also be added to an inward later.
  • Vendor categories: selected categories turn blue with a tick; vendor cards show category names; on the Vendors page, click a category to tick vendors for it directly.
New in 5.4 — GST billing through the HQ store, authorised site receipt
  1. Settings → HQ store — address & GST registration: enter the store name, legal name, GSTIN (checked for mistakes), full address, state, PIN and store in-charge. POs delivered to the HQ store then show it as Bill to & ship to, so vendors invoice on the store's GSTIN.
  2. Projects → each project: enter the site's bill-to name and, if the site has its own GST registration, its GSTIN and state. Also list the persons authorised to receive material (name, designation, mobile).
  3. Outward from HQ store: every challan to a site carries HSN, rate, taxable value and GST. Same GSTIN (or no site GSTIN) → delivery challan; different GSTIN → tax invoice with its own number. Same state → CGST + SGST; other state → IGST. Values are taken from the last purchase rate.
  4. Receipt at site: the site chooses the authorised person, uploads the challan signed and stamped at site (photo or PDF from the computer) and ticks the confirmation. Without these the receipt cannot be saved. Each site has a Received material — site record; HQ sees all receipts and missing signed copies under Dispatch to sites → Site receipts.
  5. Registers: Reports → Inward register (GST) and Outward register (GST) list every item coming into and going out of the HQ store with GSTINs, HSN, values and tax, ready for accounts. Both are also in the daily Excel backup.
New in 5.5 — pre-check of site demands
  1. Switch it on: Settings → Demand pre-check → On. From then on every new demand — whoever raises it, site or HQ — is pre-checked first and is not shown in the approver's Demand inbox until it is pre-approved. When switching on, you are asked whether demands still waiting for approval should go to pre-check too.
  2. Choose the pre-checkers first: Settings → HQ team & permissions → Add person → role Demand pre-checker (limit to their own sites if needed). Pre-check cannot be switched on until at least one pre-checker exists. Administrators and approvers cannot pre-check, and the person who pre-approves a demand cannot also approve it — so pre-check and approval are always done by two different people.
  3. Pre-check: new demands appear under Pre-check in the menu. Open one to change item, size, quantity or unit, remove or add items, save changes, then Pre-approve & send to approver with an optional note — or Delete demand with a reason.
  4. Approval: the approver can approve a demand only after it is pre-approved (also enforced on the server).
  5. Site: the site sees "Awaiting pre-check", then every change — what it asked for, what was changed, removed or added, by whom and when, and the note.
New in 6.5 — club sizes into one item
  1. Items typed in separately for each size (“GI UNION 32 MM - 4 NOS.”, “GI UNION 50 MM - 10 NOS.”, “GI Unions 32 mm”…) can be made one item with its sizes (“GI Union” with sizes 15 mm, 20 mm, 32 mm, 50 mm). Sites then pick the size from the list when raising a demand.
  2. Automatic: administrator → Item catalogue → Club sizes into items (or Find items → Club sizes into items…). ProcureHub finds the entries that are sizes of one item, takes the size out of the name (and drops quantities written in the name such as “- 4 NOS.”) and shows each group: the one item name, unit, category and the size each entry becomes. Correct anything, untick an entry, or tick Leave this group as it is; use Next / Previous to go through the groups, then Club.
  3. By hand: in Find items tick the entries that belong together → Club as one item.
  4. Every demand, quotation, PO, receipt, stock and consumption line is changed to the one item with its size; stock of the same size is added together. The separate old names disappear from the item list and the catalogue item gets all the sizes.
New in 6.4 — secure connection (removes “Not secure”)
  1. In the router (where port 8080 is already forwarded to the ProcureHub computer): add one more rule — port 80, TCP, to the same computer. Let's Encrypt, the free certificate authority, checks your internet name through port 80.
  2. In ProcureHub (administrator): Settings → Secure connection (https) → internet name rgsit.ddnsking.com (your dynamic-DNS name, without http://) → Switch on & get certificate. Within a minute it shows Certificate active.
  3. Everyone now opens https://rgsit.ddnsking.com:8080 — the padlock appears and “Not secure” is gone. Old http:// links and bookmarks are sent to the https address automatically. Sign in once again after the switch. Inside the office, addresses with the computer's IP (http://192.168…:8080) keep working.
  4. The certificate is free, valid for 90 days and renewed automatically while ProcureHub runs. Keep the port 80 rule in the router.
  5. If it says Let's Encrypt could not reach the computer on port 80: check the router rule, that the No-IP / DDNS name points to the office's current internet address, and that no other program on the computer uses port 80 (for example IIS). Some internet providers block port 80 for home connections; then ask them to open it.
New in 6.3 — cash (counter) purchases with two approvals
  1. Who may spend: the administrator gives the right in Settings → HQ team & permissions. For an HQ person tick Make cash purchases; for a site login tick May make cash (counter) purchases. For each person you can set a cash purchase limit per bill (₹; 0 = no limit) — a bill above it is refused.
  2. Who approves: first the approver (new right Approve cash purchases, also part of the Purchase manager role), then the final approval by the person who grants purchase orders (right Approve purchase orders — the Director (Procurement)). Nobody approves an entry they made, and the final approver must be a different person from the approver.
  3. Entering: Cash purchases → New cash purchase (sites see it in their menu): bought for a site or the HQ store, date, shop, shop GSTIN, bill no. and date, paid by cash / UPI / card, the purpose, the items with quantity, rate and GST %, and the photo or PDF of the bill (required). If part was used at once, enter that quantity and remarks about the use. The voucher number is CP/….
  4. Approval: the approver and then the final approver find it under Cash purchases → For me (with a count in the menu) and click Approve / Final approval, or Return for correction / Reject with a reason. A returned entry is corrected by the person who made it and sent again.
  5. Stock: after the final approval the items not used at once are added to the site stock (or the HQ store).
  6. Consumption later: on the entry click Record consumption, enter the quantity of each item and the remarks. It goes through the same two approvals and is taken out of stock after the final approval.
  7. Print the Cash Purchase Voucher with the names of who entered and approved it and the final approver's signature. The backup Excel has a sheet “Cash purchases”.
New in 6.2 — return material to the vendor

3. Using it at site

New in 5.1 — demand tracking and approver remarks
  • Sites track, HQ decides. Once a site sends a demand it is view only at site: no editing or cancelling. The site sees every item's stage (raised → approved → ordered → dispatched → received), who approved or rejected it and when. “Raised by me” in My demands shows only that person's demands.
  • Approver remarks. While approving, HQ can type a remark against any item, or one remark for the whole requisition in the Approve box. Rejecting needs a reason. HQ can also add a general remark any time. Remarks carry the approver's name and time, can't be deleted, and appear on the site's screen, the printed MR, the Excel demand register and the daily Excel backup.
  • Open the address on the phone, sign in, and choose Add to Home screen (Chrome menu ⋮ or Safari share button) — it then opens like an app.
  • Raise demand: tap a category, tap the item, choose the size and quantity, add a photo if useful, then Send to HQ. Items not in the catalogue can be typed, and rows can be pasted from Excel.
  • Receive material: when a truck arrives, tap Confirm receipt, enter what actually arrived, take a photo of the material or challan, and note any shortage.
  • Transfers: if HQ asks your site to send surplus to another site, it appears under Receive material. Load it and tap Mark as sent.
  • Site stock: record material used so HQ always knows what is left at site.

5. Data, backups and safety

  • All data and photos are in the ProcureHub-Data folder next to the program (photos in its files subfolder).
  • Automatic backups, no action needed: every day an Excel workbook of every record (projects, vendors, demands, quotations, POs, receipts, dispatches, site stock and its register) is saved in ProcureHub-Data\backups\excel and kept 120 days. A safety copy of the database is made every 15 minutes. If the data file is ever damaged, ProcureHub repairs itself from it at the next start. A full backup with photos is saved weekly in backups\full.
  • Protect against a broken computer: in Settings → Backup & data safety, set a Second copy folder on another disk, a USB drive, or a OneDrive / Google Drive folder. Every backup is copied there automatically. You can also enter an email address to receive the Excel file every evening (needs the email settings in section 4).
  • Back up now and Download Excel buttons are on the same page, along with a list of recent backup files you can download.
  • Moving to a new computer: copy the whole RGS-ProcureHub folder including ProcureHub-Data, or use Download backup / Restore.
  • Forgot the admin password: close ProcureHub, open Command Prompt in the folder and run RGS-ProcureHub.exe --reset-password admin. It prints a new password.

  • Site access: any person can be limited to selected sites. They then see only those sites' demands, stock and dispatches.
  • Rates are protected: people without "see rates and values" never receive vendor rates or PO values, not even in the data sent to their browser.

  • The program always keeps at least one active administrator, and nobody can remove their own administrator rights.

Sites can't open the address? (check in this order)

  1. Is the black ProcureHub window open on the HQ PC? If it was closed, or the PC restarted, nobody can connect. Start RGS-ProcureHub.exe again.
  2. Look at the "Windows Firewall" line in the black window. If it says NOT SET UP, close the window, start ProcureHub again and click Yes when Windows asks. Or close ProcureHub, right-click Fix-Network.cmd → Run as administrator, then start ProcureHub. This removes any "block" rule Windows made for the new EXE.
  3. Use the fixed address inside the office. The PC's number address (e.g. 192.168.1.20) can change after a restart. The black window and Settings → How sites connect now also show a fixed address such as http://hq-pc:8080 (the computer's name) that keeps working.
  4. Separate antivirus firewall (Quick Heal, K7, Norton, ESET…): allow RGS-ProcureHub.exe in that program too.
  5. Sites in other cities (Cloudflare Tunnel): the tunnel must point to the same port (localhost:8080) and the cloudflared service must be running on the HQ PC. A trycloudflare.com test address changes every time, so sites need the new one.
  6. Ran the new EXE from a new folder? If the black window says "no existing data was found in this folder", close it and copy the new EXE into your old folder (the one with ProcureHub-Data). Your data is safe in the old folder.
